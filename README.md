# sendguard — a file-name pre-flight check, ported to six languages

Point it at a folder and it tells you which file names will break on the recipient's machine, before you
hit send.

The same core exists in six implementations. **They are required to give the same answer, and there is a
gate that decides whether they do.** The gate separates the answer from the asking: the checker's verdict on
a name must be byte-identical across the six, while what each language's own standard library did when asked
is the matrix, not a failure. That gate, not the language count, is the point of this repository.

Everything below asks this repository's own legs. If you came to hold a port in your hands instead - build it, run
it, produce its face yourself - §7 is that path, and it was walked in a fresh clone before it was written down.

## 1. Verify first; the claims come after

```
git clone <this repo> && cd sendguard
python ci/selftest.py --scratch-root ../sg-selftest   # proves every gate can pass AND can fail
python ci/equality.py                                 # six ports, one frozen spec, same verdict bytes -
python ci/coverage_report.py                          # and who actually answered (a blank is not agreement)
python ci/validate_cells.py --selftest                # the outside ruler for cell conformance, both edges
python ci/spec_drift.py                               # which spec fingerprint each compared cell carries
python ci/gap_report.py                               # which required cells each port has not answered
python ci/matrix_table.py                             # the (cell x port) grid, and which field differs
python ci/expected_summary.py                         # sealed expectation vs measured, row by row -
                                                      #   including the macOS/Ubuntu rows nobody has run
python ci/triangle.py                                 # ports vs expectation vs the machine's own tools
python ci/acceptance.py                               # what each lane claims vs what the tree holds
python ci/evidence_table.py                           # regenerates docs/evidence.md from the committed data
python ci/status_brief.py                             # the one screen of numbers everything else quotes
python tool/check.py --name "trail."                   # the deliverable: one name, asked on this machine
```

Exit codes are documented in each file. `ci/selftest.py` feeds a one-byte difference, a flipped verdict, an
invented status word, a crash record passed off as a measurement, a failed control and two spelling-drift
cases into the equality gate, and it also requires the gate to **say yes** to a genuinely equal pair, to say
yes when two ports spelled the same cell differently, and to refuse to fold a bare case id into a member it
cannot prove. A gate that has only ever been seen refusing is not proven to work.

Nothing below is worth believing that those commands do not back up. Each one regenerates or judges from
the committed files, prints its own denominator, and exits non-zero rather than reporting a clean run it
cannot show.

## 2. What is evidenced

[`docs/evidence.md`](docs/evidence.md), generated by `ci/evidence_table.py` from the committed result files
and the commit they came from. It is not hand-edited: a row that cannot be reproduced is removed rather than
explained. Read its header for the current equality verdict, and [`docs/STATUS.md`](docs/STATUS.md) for the
per-cell counts (24 cells with no verdict conflict, 20 with conflicts, 13 legality abstentions, as of the
last regeneration - and of those 24, **only 4 have every verdict field recorded by every port**, which is the
difference between "nobody contradicted" and "everybody answered"; the blanks and the per-port coverage table
are in [`docs/coverage.md`](docs/coverage.md)).

The reproducibility promise was checked from a stranger's tree, not asserted: `--no-local` clone, clean
status, every leg green inside the clone (self-test 21 arms, lint 24, cell conformance 29, spec-drift 15, delivery
form 18 - the earliest recorded run listed 18 lint arms because three legs did not exist yet), the eight
published spec digests recomputed from the clone's own object store, and the gate's verdict identical to the
author's tree. Twelve derived faces were then compared with the lines that are allowed to differ declared
first: eleven identical, the twelfth differing only in the commit and the working-copy count it names - a
self-reference lag a generated file cannot avoid, so the generator now says so in that line. Runs with their
limits and the numbers that moved between them:
[`evidence/S10/cold-clone-20261011.md`](evidence/S10/cold-clone-20261011.md),
[`evidence/S10/cold-clone-20261011b.md`](evidence/S10/cold-clone-20261011b.md),
[`evidence/S10/cold-clone-20261011c.md`](evidence/S10/cold-clone-20261011c.md), and the two that found the
delivery form's four defects
[`evidence/S10/cold-clone-20261011d.md`](evidence/S10/cold-clone-20261011d.md).

That rehearsal is no longer a habit of one window: `python ci/clone_parity.py --scratch-root ../sg-parity` does it
as a leg - `--no-local` clone, `ci/refresh_all.py` run inside the clone, then every generated face compared with
the blob the clone checked out. It refuses a scratch root it did not get, refuses a drive root, refuses to nest a
clone inside the repository, never deletes anything (an existing clone is adopted only if its HEAD equals the
source's and its status is empty), and allows a difference only where the line shape was declared in advance. Its
own arms are 18, both-sided, and `--source` lets it verify the published repository instead of this working
   copy - `python ci/clone_parity.py --scratch-root ../sg-public --source https://github.com/kinsin818/sendguard` reads
   `OUTCOME=CLEAN faces_compared=13 identical=11 declared=1 differing=0 missing=0 host_bound=1` with that URL as the source; reading from this tree: `OUTCOME=CLEAN faces_compared=13 identical=11 declared=1
differing=0 missing=0`, where the one declared face is `docs/evidence.md` naming the commit it was generated
under.
Its red side was probed on a tampered generated face held in an unreachable probe commit, and it refused:
`evidence/S11/parity-red-probe-20261011.md`. The same leg also asks the deliverable itself - `tool/check.py` run in the working copy
and in the clone over five declared names, handed to the checker as hex so the probe cannot change which
name is meant - and compares the eleven fields the gate scores: `tool| names=5
fields_compared=55 differing=0`, on one host and one interpreter, which is what it says it proves
(`evidence/S11/tool-coldrun-20261011.md`).

The coverage report, which is the face that says who answered rather than who agreed, runs its own 9 arms
both-sided (`python ci/coverage_report.py --selftest`), and it refuses to publish at all when the gate's
artifact does not carry the per-port answer counts its blank attribution needs - it will not guess a
coverage number from the raw faces, because a second ruler is this project's oldest defect.

**Currently not evidenced, and therefore not claimed anywhere:** macOS and Linux rows - and the blocker is not `git push`. The sealed table already holds 22 macOS and 22 Ubuntu predictions, but no port harness can emit them: every runner writes `results/<port>.windows.x64/` by hard-coded path and probes Windows-only semantics (`docs/tickets/SG-F3-os-portability.md`). A new `instrument` job in `.github/workflows/matrix.yml` is written to re-verify the **instrument** on all three operating systems - **it has never run, because nothing has been pushed** - and the workflow file states in its own steps that it produces no result faces,
mobile storage and download layers, cloud-drive and mail-attachment renaming, exFAT/FAT32 volumes,
unsigned-executable launch behaviour, and any agreement between ports that the gate has not certified.

## 3. Capability claim vs evidence claim

* **Capability claim (judgement, mine):** the pipeline below is not specific to these six languages. Given a
  written requirement, a target language and a target runtime, the same process produces and audits the
  port; adding a seventh language is a work order, not a research problem.
* **Evidence claim (checkable by you):** exactly the ports and operating systems named in
  `docs/evidence.md` have been built, run and made to agree under one frozen specification - and the gate
  above tells you whether they currently do.

This is a delivery process, not a vocabulary of six syntaxes. It does not declare success because code was
generated: a port's committed results were **rejected by the gate** and sit unread in `results/node` (31 of
their cells carried a self-declared instrument failure and a runtime crash message), the first version of a
contract file published by this seat was withdrawn by name inside the file after it turned out to be derived
from a mis-parse, and the equality gate reported 29 of 29 cells as failing until the disagreement was traced
to how four ports had *written down* one fact - which was this repository's own defect, not the ports', and
is recorded in `docs/FINDINGS-rev6.md` section M5 rather than smoothed over.

## 4. The discipline, and what each piece stops

| step | artifact | failure it catches |
|---|---|---|
| one frozen spec, hashes published before any port runs | `spec/FROZEN.md`, `spec/cell-identity.md` | six private interpretations of one requirement |
| samples stored as hex only, never materialised as filenames | [`spec/cases.yaml`](spec/cases.yaml) | editors and transports silently corrupting the input |
| byte-stable checkout (`-text`; 384 of 388 files used to differ between commit and clone) | `.gitattributes` | an OS rewriting bytes and destroying reproducibility |
| a required-cell list generated from the spec, not hand-typed | [`spec/cells-required.json`](spec/cells-required.json) | three ports answering three different questionnaires and calling it agreement |
| independent enumerator, not the port's own report of itself | [`harness/audit.go`](harness/audit.go) | a program claiming it wrote a file the disk never received |
| per-cell child process, external 5 s timeout, no in-process calls | `harness/` | one hung probe eating a whole run |
| expectation table written by a window that wrote no port and no skeleton | [`spec/expectations.sealed.md`](spec/expectations.sealed.md) | six ports agreeing on a shared misreading |
| outside referee: the machine's own tools | [`evidence/S00/referee-windows.md`](evidence/S00/referee-windows.md) | our code and our own expectations being each other's only witness |
| equality gate that refuses to compare unequal sets | [`ci/equality.py`](ci/equality.py) | comparing an intersection and reporting a pass |
| representations folded before judging; absences never folded into answers | `ci/equality.py`, `spec/cell-identity.md` §9 | four spellings of one fact reported as four disagreements |
| the checker's verdict separated from each language's own stdlib behaviour | `spec/cell-identity.md` §9.3 | calling the matrix a failure, or calling a shared bug agreement |
| one canonical result face per port, others named and unread | `ci/blobhash.py`, `ci/evidence_table.py` | nine rows for six ports, and a denominator that means nothing |
| two-sided self-test for every gate | [`ci/selftest.py`](ci/selftest.py) | a gate hard-wired to green - which this project actually shipped once |

## 6. Status

Every count printed in this file or under `docs/` is a reading of **this repository at the commit that generated
it**, not a property of the project forever. That is especially true of the disclosure leg: re-run
`python ci/process_leak_scan.py --repo-root .` and it answers for the checkout you are standing in, printing each
class with its own count and the denominator it scanned. On 2026-10-12 this project published a set of those
numbers that its own needles could not see - paths written with escaped separators were invisible to the comparison
- so the figures printed that day understated the tree they measured, and the errata ledger
([`docs/FINDINGS-rev6.md`](docs/FINDINGS-rev6.md), entry M12) says by how much and which faces carried them. The
rule for a reader is therefore the rule this repository applies to itself: **a count quoted without the command
beside it is a count to re-measure before repeating.** Nothing was retro-fitted to make the published numbers look
better, and the published history was not rewritten to hide them; the correction travels forward only.

Under construction. `docs/evidence.md` carries the current verdict line, regenerated from the committed
result files; `docs/GAP.md` carries the required cells each port has not answered yet, by name. Until
`ci/equality.py` prints `OUTCOME=PASS`, treat §1's claim as unverified and the project as unfinished - that
is the honest reading of both files as of this commit. A cell that no port answered is a gap; a cell whose
ports asked different layers is listed as not comparable, with the reason; neither is counted as agreement.

## 7. Running a port yourself - the stranger's path

A reader who wants to hold one port in their own hands, rather than read this repository's word for it, needs a
toolchain and three commands per port. The table below is the path walked end to end on 2026-10-12 in a
`--no-local` clone of the tip: every row was typed as written, in that clone, and each port's produced face was
then compared field-by-field against the face this repository commits - **zero differences in any verdict field**
across all six canonical faces; only timestamps, elapsed milliseconds and scratch-directory fields move, which is
what a re-run is allowed to move. Re-check the versions you have before starting:

```
python -V && node -v && go version && rustc -V && javac -version && dotnet --version
```

| port | build | run the whole face | focused run (fast, proves the wiring) | what it prints |
|---|---|---|---|---|
| `python-port` | none - standard library only | `python impl/python/sg_run.py` | `python impl/python/sg_run.py --len-only` (twelve length cells plus the five controls) | `cells_written=`, `control_all_ok=`, `producer_keys_purged=` and its own scratch root |
| `rust-port` | `cargo build` inside `impl/rust` (the runner builds the two faces it needs) | `python impl/rust/run_cells.py` | `python impl/rust/run_cells.py --phase controls` | per-cell control verdicts, then `controls_pass=`, `cells_produced=`, `problems=` |
| `typescript-port` | no transpile step - node strips the types; the load test is `node --experimental-strip-types --check impl/typescript/src/runner.ts` | `node impl/typescript/src/runner.ts` | same command; it plans and runs the whole grid | `written=`, `cells_expected=`, `controls_pass=` |
| `go-port` | `go build ./...` in `impl/go`, `go build` in `impl/go/rederive`, and `go build audit.go` in `harness` (three modules, one per instrument) | build the re-derivation tool and run it against this tree, giving it the results directory explicitly: `go build -o <outside-the-tree>/sg-rederive.exe ./impl/go/rederive` then `<that binary> run --repo . --results results/go.windows.x64` | add `-only ctrl` to that run | `cells_planned=`, `cells_written=`, `controls_pass=`, and a manifest path it writes under `evidence/S02/` |
| `java-port` | `javac -nowarn -encoding US-ASCII -d impl/java/build impl/java/src/*.java` | `python impl/java/tools/run_cells.py` | add `--dry` for plan-only, no measurement | one `CELL` line per cell including the five `ctrl` rows, then `cells_produced=`, `missing_required=` |
| `csharp-port` | `dotnet build` inside `impl/csharp` | `python impl/csharp/run_csharp.py --all` | `python impl/csharp/run_csharp.py --controls` - **and note this mode deliberately reports `missing=43`**: it runs the five controls only, and the harness prints the required list it did not cover instead of pretending | `cells_run=`, `required_ids=`, `missing=`, the dotnet version it found, and `stale_files_on_disk=` |

Three honest caveats, because this is the part a README usually omits and a reader then discovers:

- **`rust-port` needs a crate download on a truly cold machine.** Its two normalisation dependencies are not
  vendored into this repository, so `cargo build` requires registry access the first time; the run quoted above
  succeeded with `--offline` because the host had a warm cache, which is not a stranger's starting condition.
  A stranger without that cache should expect to need network once.
- **`java-port` has no lane-authored self-check file.** The other five lanes ship a `selfcheck` script that
  re-parses the contract and judges the lane's own face independently of the shared rulers; the Java lane's
  control assertions are its run output plus `ci/validate_cells.py` and `ci/equality.py`, which every face passes.
  The asymmetry is real, is recorded in `docs/tickets/SG-F16-java-lane-selfcheck.md`, and does not currently
  weaken any published reading.
- **This is one host, one Windows edition, one set of toolchain versions.** `docs/host-stamp.md` prints what this
  machine is, the cold-clone leg quarantines it by name rather than comparing it, and the ports' disagreement about
  things like prefix handling is the product, not noise. If you run a port and get a different verdict field, that
  is not a README problem to file - it is a result this project's gate would want: run `python ci/equality.py` in
  your checkout and report the line it prints.

If you want the whole repository to prove its own reproducibility rather than ask you to trust it, that is one
command and it is meant to be run against a fresh clone of a remote, not a directory copy: `python ci/clone_parity.py
--scratch-root ../<your-dir>`, and with `--source <url>` pointed at the published repository.
