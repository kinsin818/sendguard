## What changed, and which of it was my defect

1. **Representations are folded before anything is judged.** In the rev5 run four ports recorded one
   control cell identically (create `ok`, 28 written, 28 on disk, read `ok`, `legal`, the same payload
   digest `c9fe45b2…`) and the gate called it a disagreement, because the landed name was hex in two ports
   and text in two, and the length triple was a dict in one, `15/15/15` in another, `[15,15,15]` in a third,
   and omitted in a fourth. That is my contract's fault for not pinning the shape, not yours.
   `name_encoding` and `length_unit` no longer enter the comparison, and neither do `control_pass` /
   `instrument_red` — those are health declarations the health leg already reads.
2. **Spelling drift is folded where the record says which cell it is**: `BLIND-1` / `T-BLIND-1` → `B1`;
   `T09a` → `T09-m1`; `T17-GRID-B120-L137` → `T17` **only** when the base length inside the id equals the
   cell's own `base_len`. A bare `T09` is **not** folded into a member — say which member you measured.
3. **Two classes of field.** `VERDICT_FIELDS` (the checker's answer about the name: legality verdict,
   mechanism class, phantom, roundtrip, mutation, enum/stat agreement, length triple, bytes written, bytes
   on disk, the name the directory enumerates) must be byte-identical across ports — that is the claim.
   `PROBE_FIELDS` (`create_result`, `error_stage`, `read_result`, `path_form` choice,
   `longpath_mechanism`, `deps_*`) are what *your* language's standard library did; they are allowed to
   differ, they are published as the matrix, and the gate no longer calls them a failure.
4. **Cells that are not the same question are named, not judged**: different `path_form` or
   `verdict_via` → `incomparable`; different input bytes → `unpinned_input`.
5. **Only `results/<port>.<os>.<arch>/` is read.** `results/` currently also holds `python`, `node`,
   `go.windows.go1.23.5`, `node.windows.22.22.2.json`, `python.windows.3.14.7.json` — earlier revisions of
   the same ports. They stay on disk and are listed by name; they are not folded into a denominator.
6. **The five control cells now have pinned sample bytes** (`control_samples` in `spec/cases.yaml`). This
   was a real hole, measured: the same cell id `T-CTRL-CANON` arrived as `canon-csharp.txt`,
   `canon-go-arm.txt`, `canon-python.txt` and `report-2026.txt`, and two different payloads were hashed
   under it. Use the pinned `sample_hex` and the pinned 28-byte payload
   (`SENDGUARD-CANON-PAYLOAD-2026`, sha256 `c9fe45b2…`) for all five control cells.
