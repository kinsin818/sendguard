# sendguard · 文件名体检报告

同一个文件名能不能存，取决于三件互不相干的事：**你用哪门语言数它、你把它放在第几层目录、以及收文件的人用什么系统。**

这份报告的全部结论，每一行都带一条能重跑的命令。跑出来不一样，就是这份报告错了——`docs/expected-summary.md`
里"预期 vs 实测"逐行对照已经先记了三条我们自己预测错的行（见 §5）。

**文中所有计数是 2026-10-11 05:1x +0800 的读数，不是终态。**各门仍在补格，重跑下面的命令会以同一条
`OUTCOME=` 行覆盖这些数字；一个数字对不上，就以命令输出为准、以本文为错。

复现入口：

```
git clone <本仓> && cd sendguard
python ci/selftest.py --scratch-root ../sg-st      # 14 条臂，闸必须既能判红也能判绿
python ci/equality.py                              # 六门 × 冻结规范：判定字段是否逐字节相同
python ci/gap_report.py                            # 每门还差哪些格，按名字列出来
python ci/expected_summary.py                      # 预期 vs 实测，含"没跑"和"接不上"两种诚实状态
```

## 1. 这份东西是怎么造出来的

一份冻结规范（20 条陷阱 + 5 个控制格 + 5 个盲样本 + 每语言钉死的 API 入口，样本一律 hex 存字节），
六个人互不可见的窗口各写一门：TypeScript(Node 24 去类型)、Python、Go、Java、C#、Rust。
**没有跨语言调用，没有共用工具函数，没有互相抄。**判定只看一件事：同一格上，六门交付的报告字节是否相同。

规范的哈希在任何一门跑之前公布（`spec/FROZEN.md`，8 件产物）。期望表由一个既不写门也不写骨架的窗口
先写好封存（`spec/expectations.sealed.md`），六门全跑完才打开对照——这一条是为了抓第六种失败：**六门
一起读错同一句话**。

## 2. 六门一致的地方（这才是可交付的证据）

在当前提交上，六门都答过的 17 个可比格里，**12 格里没有任何两门的判定字段互相冲突**（写法已归一，缺记的字段单列，不算同意）：

```
python ci/equality.py | grep cells_with_no_verdict
```

- `T06` emoji、`T07` NFD、`T08` NFC、`T09-m1`/`T09-m2`（同一目录 NFC 与 NFD 共存）、`T12` 双向文字
  U+202E、`T13` 零宽 U+200B、`T15` 控制字符、`T19-m1` 全角、`T19-m2` 韩文자모、`T20` `--force.txt`、
  外加一个控制格（`T-CTRL-ASCII`），共 12 格。

值得停一下的是这一组的构成：**六门全部一致的，正是 Unicode 归一化类**。同一份规范被六份互不可见的实现
读过之后，归一化的结论没有一门例外——这是"规范写得清楚到能被独立复现"的证据，不是语言味的巧合。

## 3. 六门不一致的地方（这才是要卖的东西）

剩下 5 格产生 19 条判定冲突，全部集中在**同一台 Windows 上不同 API 层的策略**：

```
python ci/equality.py | grep VERDICT-DISAGREE
```

| 陷阱 | 六门的回答 | 一句话 |
|---|---|---|
| `T04` 结尾点号 `trail.` | 4 门"合法、落盘改名"，2 门"非法"；1 门"没改名"；1 门报盘上 0 字节而另四门报 28 字节；1 门同时记了请求 6 与落盘 5 | 尾点剥离不是 Windows 的属性，是你调的那个 API 的属性 |
| `T05` 结尾空格 `trail␣` | 同上分裂 | 同上 |
| `T03` `a<b.txt` | 5 门"非法"，1 门"合法" | 加了 `\\?\` 前缀之后 `<` 就合法了——问题不在文件系统，在你问的是哪一层 |
| `T16` zip 打包回读 | 同一个名、同一份载荷，三门 28 字节、一门 296、一门 292 | 压缩库在"要不要置 UTF-8 标志位"上分成三派，Mac 的包到 Windows 变形就是这里 |
| `T-CTRL-ILLEGAL-CHAR` | 5 门报控制格应有的拒绝，1 门"合法"、1 门"不分类" | 连校准格都校准出两种世界 |

这五行没有一行需要解释谁对。**它们就是产品**：任何一个用单一语言写成的"发件前体检器"，
都会在同一台机器上对同一个文件名给出与另外五门不同的答案；把检查建在其中任何一门之上，都是在赌
客户端和收件人恰好没有被那一层的策略坑到。

## 4. 长度这件事上，两个尺度不是一回事

`T17`（全路径逼近 260 码元）与 `T18`（单个组件逼近 255）必须分开问，而且必须 `\\?\` 开/关各问一次。
本机当前读数：普通路径受"根目录长度 + 组件"总量 259 约束，带前缀才看见 255 的组件上限；
`LongPathsEnabled=0`，而是否放行还取决于**每一枚 exe 自带的清单**——这是按可执行文件生效的属性，
不是按语言生效的属性。三档 emoji 样本（15/40/60 个家庭 emoji）按码元判定与按字节判定结论相反，
所以表 A 里长度一律记 `码点 / UTF-16 码元 / UTF-8 字节` 三元组，禁止写成单个数字。

```
python ci/equality.py | grep "len/T1"
```

## 5. 我们自己错在哪（原始输出照印）

- **预测错**：封存期望表在 `T01 CON.txt`、`T10 CON`、`T11 COM1.log` 上预测读结果为 `hang`；
  五门交回 `not_applicable`（根本没落盘，就没有可读的那条腿），一门交回 `eof`。
  ```
  python ci/expected_summary.py | grep CONTRADICTED
  ```
- **量错**：等值闸一度报"29 格全红"。逐格回读发现四门在同一格上记的是**同一个事实的四种写法**
  （hex 与明文；长度三元组的 dict、`15/15/15`、`[15,15,15]` 与被省略）。闸把写法当成分歧，
  就会把真正值得看的五行埋掉。修的是闸，不是门。
- **发布过一份错的必交清单**：第一版 `spec/cells-required.json` 来自一次错解析，只看见 20 条陷阱、
  漏掉控制格与成员分裂。文件里按名字撤销了自己，下游一律以重新生成的版本为准。
- **一把只会说"不"的闸**：`ci/selftest.py` 现在有 14 条臂，其中三条专门证明它会放行——
  `green-identical`、`probe-difference-is-data`、`alias-folds-spelling-drift`。
  ```
  python ci/selftest.py --scratch-root ../sg-st | grep -E "arms=|OUTCOME="
  ```
